# 故事逻辑检查

定位：**只检查，不创作**。读取 `story/<slug>/` 下已产出的交付物，输出一份**带逐字引文**的逻辑矛盾报告。承接 `story-localize-video`（内容侧产出）与 `agnes-media`/`agnes-video-director`（执行侧），在**交付前**把"打勾清单"升级为"逐条比对校验"。

与现成"章节制长篇小说连续性检查"（story-consistency-monitor / plot-consistency-checker 等）的区别：那些面向 30k+ 字手稿与 story-bible 结构，本 skill 面向**短篇公版改编 → ≤12s 分段 → scenes.json** 的管线，额外锁定**改编内核保值、经济/时代重校准、护照↔分镜交叉、world-bible 宇宙一致**四类专属问题，同时吸收其通用的因果/时间/知识状态维度。

---

## 一、运行时机（Gate）

- **必跑**：`03_script.md`、`06_storyboard.md`、`scenes.json` 任一产出/改动后，正式交付前。
- **重跑**：剧本/护照/分镜任何文件被修改后，报告作废重出。
- 全案交付时，报告结论作为 `07_publish.md` 前的最后一道闸门。

## 二、输入

| 输入 | 用途 |
|---|---|
| `story/<slug>/01_beats.md` | 内核（不可变项）与因果链基准 |
| `story/<slug>/02_adaptation.md` | 结构公式 vs 本次填充的符号变量 |
| `story/<slug>/03_script.md` | 检查剧本层逻辑 |
| `story/<slug>/04_roles.md` | 角色护照：交叉引用基准 |
| `story/<slug>/05_scenes.md` | 场景/物件/光线设定 |
| `story/<slug>/06_storyboard.md` + `scenes.json` | 分段因果链、字段完整度、首尾帧衔接 |
| `story/_universe/world-bible.md` | 宇宙一致性基准（若本次新增地点/机构） |

只给了部分文件？照查，报告里标注"未覆盖项"，不因此放宽已覆盖部分。

## 三、方法：先建"逻辑账本"，再逐条比对

### Step 1｜抽取账本（从 01/03/04 等文件）

1. **角色事实表**：姓名、年龄、外貌（发型/脸型/服装/道具/体态）、关系称谓、性格关键词、经济状况。
2. **因果链表**：01 的内核事件顺序 + 03 剧本中每个"因为 X 所以 Y"。
3. **时间线表**：故事总时长、日夜/季节/年龄推进、闪回与倒叙标记。
4. **伏笔/反转表**：铺垫在哪（文件+行）→ 回收在哪（文件+行）；反转句实际落点。
5. **经济/符号表**：钱、物价值、收入、期限、时代符号（物件/称谓/货币单位）。

### Step 2｜比对

对账本内每一项做三类交叉：账本内自洽、账本↔剧本/分镜、剧本↔护照↔scenes.json。发现冲突即入报告，逐字引用两处矛盾文本。

---

## 四、检查维度（七类）

### 1. 内核保值（改编专属）🔴
- 01 声明的**不可变内核**（反转机制/因果链/主题/情感落点）在 03/06/scenes.json 是否被削弱或丢失。
- 02 结构公式的**函数本身**是否被改写（替换变量可以，替换函数不行）。
- 反转句是否仍在**最后一段的结尾字幕/旁白**；是否有提前泄底。
- 开头 3 秒冲突段与结尾反转是否构成同一根因果线。

### 2. 因果链与段间黏合（通用 + 管线）🔴
- 相邻段（含 scenes.json 相邻 id）"因为 A 所以 B"是否断链、是否出现无承接硬切。
- 剧本事件顺序是否符合 01 因果链（原因先于结果）。
- 反转是否成立的前置信息都已被铺设（反转所需的"钩子信息"不能在反转点才凭空出现）。

### 3. 知识/信息状态（通用）🔴
- 角色是否说出/做出他**当天没有途径获知**的信息（谁告诉他的？他偷听到没有？）。
- 旁白/字幕是否透露了当前镜头内角色不该知道的秘密。
- 反转信息线的"观众知道 / 角色知道"差量是否一致（不能观众提前知道太多而角色毫无反应）。

### 4. 角色一致性（通用 + 护照交叉）🟠
- `04_roles.md` 护照字段（发型/服装/道具/年龄/关系/性格词）↔ `03_script.md`/`06_storyboard.md`/`scenes.json` 描述冲突。
- 动机突变无铺垫；技能/能力突然出现或消失。
- 称谓漂移：同一角色在不同文件里名字/称呼不一致（含"雅诗/林雅诗/林总"类缩称）。

### 5. 经济/时代/符号校准（改编专属）🟠
- 经济账是否成立：如《项链》"十年还债"需物价值 ÷ 月收入 ≈ 120 个月，明显不成立即为矛盾。
- 中文化替换后贫富/阶层符号是否重新校准（原著"舞会礼服"换成当代等价物时，代价感不能缩水）。
- 时代自洽：当代设定里不出现年代不符的物件/称谓/货币。
- 互换术检查：把 02 映射表里每个"原著符号→中文替身"反向代入，故事是否仍然成立。

### 6. 时间线（通用）🟠
- 时间流逝自洽（年龄、季节、日夜、时长）；闪回/倒叙是否有明确标记。
- 同一事件在不同文件（03 的时间轴 vs 06 的段序）排序一致。

### 7. 世界观宇宙一致（管线）🟡
- 新增地点/机构是否已回写 `world-bible.md`（地图上不出现两个同名城市）。
- 与既有宇宙命名冲突（重名/近似撞名）。
- 禁用项复查（真实地名/品牌/名人/机构名——可 `grep` 扫 03/04/05/06/scenes.json）。

## 五、输出格式（一份 markdown 报告）

```
## 逻辑检查报告 — <篇名>
结论：✔ 通过 / 🟡 有条件通过（N 项待确认）/ ✘ 不通过（M 项必改）
覆盖范围：已检查 [文件清单]；未覆盖 [文件清单]

### 🔴 必改（不修不交付）
| # | 位置(文件:行) | 引文 | 问题 | 证据 | 建议修法 |
### 🟠 建议修（影响观感/可信度）
| # | 位置 | 引文 | 问题 | 证据 | 建议修法 |
### 🟡 提示（可能是设计，需用户确认）
| # | 位置 | 引文 | 疑问 | 需要确认什么 |
### ❓ 待确认项（结论为"有条件通过"时列出，用户逐一裁决后才算通过）
```

- 结论为 🟡 时，**必须**列出待确认项清单，用户逐项回复后才可视为通过。
- 建议修法只给 1 个方向，**不代改原文、不替用户定 canon**（参考 continuity-editor 纪律：只让冲突无法被忽视）。
- 每条引文必须逐字取自文件，禁止凭印象复述；无引文支撑的怀疑降一级或入待确认。

## 六、纪律

1. **只 flag，不改稿**：canon 归用户；报告只指出冲突与证据。
2. **引文逐字**：每条结论必须可回指到文件原文。
3. **区分"真矛盾"与"可能是设计"**：梦境/说谎/不可靠叙述/时间跳跃是有意设计的，先标注为 🟡 待确认，不直接算 bug。
4. **不评判文笔与审美**：只查逻辑；好稿坏稿都过，只要自洽。

## 七、与流水线的衔接

- 由 `story-localize-video` 在阶段 4/5 产出后、正式交付前调用本 skill 跑报告；报告结论写入交付记录。
- 本 skill 不写任何 `story/<slug>/` 文件（只输出报告文本），不修改 scenes.json。
